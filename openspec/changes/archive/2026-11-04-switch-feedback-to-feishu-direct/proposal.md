# 反馈通道改为飞书直发

- 日期：2026-11-04
- 状态：提案已建立，待实施
- 范围：反馈提交端（App → 飞书），不改认证核心与既有协议

## Why

上一版（change `add-app-feedback-channel`）实现了自托管收集端：作者在自己机器上跑
`oit-portal feedback serve`，同学的手机把反馈 POST 给这台机器。

用户明确反馈：**不想一直开着电脑的一个端口服务**。校园网环境下的自托管还有两个现实问题：

1. 电脑关机 / 换网络 / 睡眠 → 同学提交全部失败，且同学不知道该找谁说；
2. 作者要随时能看反馈，就必须让那台机器一直在线。

飞书是常驻云服务，作者不占任何一台机器。把提交端从「作者机器上的临时服务」改成
「飞书 webhook」，电脑不用开。

## What Changes

1. **App 提交目标改为飞书 webhook**：App 内填的地址改为飞书 webhook 地址，
   不再需要作者机器上跑服务。
2. **按通道形态构造请求体**：飞书两种 webhook 的请求体不同，本地实现按地址形态自动区分——
   - 群机器人（`/open-apis/bot/`）：`{"msg_type":"text","content":{"text":...}}`
   - 多维表格（其它形态）：扁平 JSON，键名即表格列名
3. **支持飞书凭证校验**：
   - 群机器人签名校验（`timestamp` + `sign`，HMAC-SHA256 后 Base64）
   - 多维表格 Bearer 凭证（`Authorization: Bearer <token>`）
4. **表格列名与载荷对齐**：载荷增加 `category_label`（中文分类）与 `submitted_at`，
   使多维表格可以直接建「分类」单选列与「时间」列并按其筛选。
5. **保留自托管收集端**：不删除，作为「需要先审后收」或「完全离线」时的可选项，
   CLI 的 `feedback list` / `export` 仍然服务这条路径。

## 不做什么（Non-goals）

- 不改认证核心、SSO/ePortal 流程、CAPTURED 协议常量块。
- 不引入飞书开放平台应用（app_id/app_secret），不用多维表格开放 API 写入。
- 不做反馈的审核 / 回复界面（作者在飞书里直接看表格）。
- 不删自托管收集端，也不改它的落盘与转发语义。

## 影响范围与安全边界

- **改动 Python**：`oit_portal/feedback.py`（提交层按通道构造请求体、凭证校验、载荷补字段）。
- **改动 Android**：`core/FeedbackSettingsStore.kt`（地址语义 + 凭证）、
  `core/ChaquopyFeedbackBridge.kt`（传凭证）、`ui/FeedbackForm.kt`（文案不再说「只存在作者本机」）。
- **安全边界（重要）**：
  - 飞书 webhook 地址是**写入凭据**。它会随 APK 分发，因此**可被提取**。
  - 缓解手段由飞书侧提供，**必须在飞书后台开启**：
    - 群机器人 → 「签名校验」（HMAC-SHA256），或「自定义关键词」
    - 多维表格 → 「凭证校验」（Bearer token）
  - 因此 App 内**必须能携带凭证**，否则对方一开校验就全部投递失败。
  - 凭证只用于**写入这一个通道**，不能读写其它数据；泄露的后果限于「能往该表/群写内容」。
  - 反馈载荷仍只含同学填写的正文与脱敏摘要，不含账号、密码、Cookie、完整 URL。
  - 提交继续走 `network.create_session()`（`trust_env=False`）。
  - 收集端地址与凭证不进 Git 仓库；仅以构建期默认值形式出现在 APK 中。

## 验收标准

- App 里把地址填成飞书 webhook 后，同学提交能落到飞书（群消息或表格记录）。
- 群机器人地址与多维表格地址各自构造出正确的请求体形状。
- 开启飞书签名校验（群机器人）或 Bearer 凭证（多维表格）后，提交仍然成功。
- 飞书返回 `code != 0`（如关键词不匹配、IP 不在白名单）时，App 给出明确失败提示，
  而**不是**显示「提交成功」。
- 自托管收集端路径不受影响：`oit-portal feedback serve/list/export` 仍然可用。
- `python3 -m pytest` 全绿；Android `testDebugUnitTest`、`assembleDebug`、`lintDebug` 通过。
- 文档给出可照做的飞书配置步骤（建表 / 建机器人 / 取地址 / 开校验 / 建列）。

## 回滚方案

本变更不修改认证协议与既有数据格式。回滚时把 App 里的地址改回自托管收集端地址即可
（地址是运行时配置），或回滚本次代码提交。已落到飞书的反馈不受影响。
