# Android 原生客户端 UI/UX 重设计

- 日期：2026-10-23
- 状态：提案已建立，实施与验证进行中
- 范围：仅 Android 原生客户端界面层

## 为什么做

当前 PortalScreen 将连接状态、登录表单、账号/会话操作、设置和诊断事件堆叠在一个长页面中。用户需要滚动寻找功能；登录反馈主要埋在诊断区；未实现的后台自动重连也以禁用开关出现，容易造成误解。

## 做什么

1. 将界面组织为「连接 / 设置 / 诊断」三个底部入口。
2. 连接页突出当前网络状态、状态解释、登录表单和两个高频操作。
3. 设置页集中网络恢复/回到前台自动刷新、账号管理、本地会话结束与尚未接入的协议配置入口。
4. 诊断页展示操作提示和最多 10 条会话内脱敏事件。
5. 建立统一的品牌色、状态色、圆角、间距和文本层级；保持中文文案、触控面积和无障碍语义清晰。

## 不做什么（Non-goals）

- 不改 Python 认证核心、SSO/ePortal 流程、网络探测和会话桥接。
- 不实现 Capture，不实现后台自动重连，不新增权限或后台行为。
- 不改变凭据保存策略、Android Keystore 存储、密码提交前清空或日志脱敏策略。
- 不新增 UI 依赖，不要求安装到真机。

## 影响范围与安全边界

主要涉及 `android/app/src/main/java/com/oitnetportal/ui/PortalScreen.kt`、`PortalCredentialForm.kt` 和新增的主题文件；同步更新 Android 文档与源码契约测试。CAPTURED 协议常量块、安全脱敏逻辑、网络认证行为均不触碰。既有 ViewModel 回调和状态模型继续复用。

## 验收标准

- 三个入口职责清晰，首页无需先滚过设置/日志才能完成登录或刷新。
- UNKNOWN / ONLINE / CAPTIVE / OFFLINE 均有明确状态文案和视觉区分。
- 登录表单继续校验账号密码、遮蔽密码，并在提交回调前清空密码状态。
- 设置开关、账号管理、本地会话结束、诊断事件、Capture 待接入提示仍可用或被准确标明。
- `python3 -m pytest`、Android `testDebugUnitTest`、`assembleDebug` 与 `lintDebug` 通过；不要求网络访问校园网。

## 回滚方案

本变更不修改数据格式或认证协议。若界面验收不通过，可仅回滚本变更涉及的 Compose UI、主题、相关测试和文档文件；无需迁移用户数据，也无需清理 Keystore 或应用偏好。
