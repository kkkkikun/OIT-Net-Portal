# App Feedback Spec

> 版本: 1.0.0 | 最后更新: 2026-11-04

## ADDED Requirements

### Requirement: App 内的快速反馈入口

Android 客户端 MUST 在设置页提供可直接到达的反馈入口，且反馈表单 MUST 在 App 内以原生界面呈现，
MUST NOT 依赖跳转外部浏览器或第三方问卷页面。

#### Scenario: 打开反馈表单

- **GIVEN** 用户进入设置页
- **WHEN** 页面渲染
- **THEN** 页面底部显示「意见反馈」卡片，点击后在 App 内打开反馈表单

#### Scenario: 校验并提交反馈

- **GIVEN** 反馈表单已打开
- **WHEN** 用户填写的反馈内容为空并尝试提交
- **THEN** 表单拒绝提交并显示明确的必填提示；内容非空时允许提交，提交期间禁用重复提交

#### Scenario: 附带脱敏诊断摘要

- **GIVEN** 用户在反馈表单中开启了「附带诊断信息」
- **WHEN** 反馈被提交
- **THEN** 载荷包含由已脱敏会话事件构造的诊断摘要，且摘要中不含账号、密码、Cookie 或完整 URL

### Requirement: 反馈收集端

Python 核心 MUST 提供自托管的反馈收集端，MUST 将收到的反馈追加落盘为本地文件，
并在配置了飞书 webhook 地址时同步一份到飞书多维表格。

#### Scenario: 接收并落盘反馈

- **GIVEN** 收集端正在运行
- **WHEN** 收到一个合法的反馈提交
- **THEN** 反馈按 JSON Lines 追加写入本机文件，且返回成功响应

#### Scenario: 转发飞书为可选增强

- **GIVEN** 收集端未配置飞书 webhook 地址
- **WHEN** 收到反馈
- **THEN** 反馈仍然落盘，转发步骤被跳过且不影响提交结果

#### Scenario: 落盘优先于转发

- **GIVEN** 收集端已配置飞书 webhook 地址
- **WHEN** 飞书转发失败
- **THEN** 反馈已经落盘，失败只记录日志，不影响反馈被收集的事实

#### Scenario: 拒绝非法载荷

- **GIVEN** 收集端正在运行
- **WHEN** 收到缺少必填字段或内容为空的反馈提交
- **THEN** 收集端返回失败响应，且不把该提交写入文件

### Requirement: 集中处理反馈

Python 核心 MUST 提供把本地反馈集中列出与导出的命令，导出的结果 MUST 是便于逐条处理与归档的格式。

#### Scenario: 列出反馈

- **GIVEN** 本机已落盘若干反馈
- **WHEN** 执行列出命令
- **THEN** 终端按时间顺序展示每条反馈的分类、内容摘要与提交时间

#### Scenario: 导出清单

- **GIVEN** 本机已落盘若干反馈
- **WHEN** 执行导出命令
- **THEN** 生成一份 Markdown 清单，逐条包含分类、完整内容、时间与诊断摘要
