# Android UI/UX 设计说明

## 设计目标

优先级依次为：快速判断是否在线、快速完成登录、清楚理解自动刷新行为、必要时找到排障线索。视觉上轻、留白充足、层级明显；避免把首页做成技术控制台。

## 信息架构

- **连接**：状态卡片 → 重要提示 → 账号/密码表单 → 刷新状态 / 重试登录。
- **设置**：网络恢复时自动刷新、回到前台时自动刷新、已保存账号管理、本地会话操作、协议 Capture 占位入口、后台自动重连未开放说明。
- **诊断**：当前提示、会话事件数量、最近 10 条脱敏事件及空状态。

底部导航保持固定；每个页面独立滚动。账号管理仍使用现有对话框，避免引入额外导航库。

## 视觉规范

- 品牌主色：蓝色（约 #2457C5）；辅助色：青绿（约 #087F72）。
- 背景：浅灰蓝白（约 #F5F7FB）；卡片表面为白色。
- 状态色：在线用低饱和绿色、待认证用琥珀色、离线用红色、未知/处理中用蓝色；状态不能只依靠颜色，还必须显示文字。
- 卡片圆角约 20–24 dp，内容间距以 8 / 12 / 16 / 24 dp 为主。
- 标题、状态、正文和辅助说明形成清楚的字号层级；交互控件使用 Material 3 默认触控语义。

## 关键交互

- 首页始终显示状态与状态详情；忙碌时显示进度反馈并禁用重复操作。
- ViewModel 的 notice 在连接页显式展示，不再只藏在诊断页面。
- 登录表单保留账号选择、输入校验、密码遮蔽和「保存此账号」默认不勾选的安全行为。
- 「网络恢复时自动刷新」和「回到前台时自动刷新」明确说明只校准状态，不会自动登录。
- 后台自动重连以说明文字呈现，不伪装成可接入功能；Capture 保留禁用占位并明确待接入。
- 诊断事件只展示 ViewModel 提供的脱敏字符串，界面不拼接账号、密码、Cookie 或 URL。

## 方案比较

1. **单页分组（现状优化）**：改动较小，但页面仍然过长，设置和日志持续争夺注意力。
2. **底部三入口（采用）**：连接场景优先，设置/诊断各自独立，改动局限于 Compose UI，且无需导航依赖。
3. **抽屉或多级导航**：结构灵活，但在小型工具中增加一次操作成本与实现复杂度。

选择方案 2，以最少的架构变化获得清晰的信息层级。

## 依赖与边界

仅依赖现有 Jetpack Compose / Material 3。UI 只消费 PortalUiState 和既有回调；不直接访问存储、Python 或网络，不改变认证时序。凭据仍由现有组件在 Composition 中短暂持有并于提交前清空；是否持久化仍由用户显式勾选并交给既有 Keystore 存储实现。
