# Android App 部署与使用指南

> 适用对象：`android/` 目录下的路线 B 原生 App（Kotlin + Compose + Chaquopy 复用 Python 核心）。
> 命令行三端（Windows / Termux / Linux systemd）的文档见 `windows-setup.md`、`termux-setup.md`、`linux-setup.md`。

---

## 1. 安装

### 1.1 覆盖安装（升级）

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`-r` 会保留已保存的账号与设置。**不要**用 `adb uninstall`，否则 Keystore 里加密的账号会一并清除。

### 1.2 直接安装 APK

把 `app-debug.apk` 传到手机后点击安装。首次安装需要允许「安装未知来源应用」。

---

## 2. 首次配置

1. 打开 App，在「连接」页输入校园网账号（学号/工号）和密码。
2. 勾选「保存此账号」才会把凭据写进 **Android Keystore 加密存储**；不勾选则只用于本次登录。
3. 点「登录」。成功后会提示「账号已保存到本机加密存储」。

> 密码只存在于本机 Keystore 加密存储中，不会出现在账号列表、日志或诊断事件里。

### 2.1 账号与 Wi-Fi 自动匹配

「设置 → 已保存账号 → 管理」里可以给账号起别名、绑定 SSID。绑定后，只要手机连上该 Wi-Fi，App 会自动预选对应账号（**只预填表单，不会自动登录**）。

读取 Wi-Fi 名称需要系统授权：

| 系统版本 | 需要的权限 | 说明 |
|---|---|---|
| Android 13+（API 33+） | `NEARBY_WIFI_DEVICES` | 不涉及定位 |
| Android 12 及以下（API ≤32） | `ACCESS_FINE_LOCATION` + `ACCESS_COARSE_LOCATION` | 系统限制，缺失时只能手动选账号 |

未授权时「连接」页会提示，点一下即可弹系统授权框。

## 3. 后台自动重连（核心功能）

「设置 → 后台自动重连」开关，默认**关闭**。开启后：

- 前台 Service 常驻，每 60s 巡检一次；断网时降为 30s 监测。
- 只有在探测到「需要校园网认证」（CAPTIVE）时才会自动提交凭据登录。
- 两次重登之间至少间隔 300s；连续 3 次登录失败会停止并请求人工介入。
- 常驻通知里带「停止」按钮，可一键关掉。

> **开启前必须先有已保存的账号**，否则开关会拒绝开启并提示。

### 3.1 ⚠️ 必须手动允许通知（vivo / OPPO 等厂商必读）

**部分厂商系统默认禁用应用通知**（vivo Funtouch、OPPO ColorOS 实测如此）。此时：

- 后台自动重连**照常运行**，但常驻通知与「登录失败需人工介入」的提醒**完全不显示**；
- 用户看到的是一个"静默"的应用，容易误以为没在工作。

开启路径（vivo 实测）：

> 设置 → 通知与状态栏 → 应用通知 → 找到本应用 → 打开「允许通知」

OPPO / 小米 / 华为等路径类似，都在「设置 → 通知管理 → 本应用」下。

**App 内已内置检测**：只要后台重连开着而系统通知被禁用，「设置」页会立刻出现红色的「系统通知已被关闭」提示卡，并附带「打开通知设置」按钮直达系统设置页。

### 3.2 Android 13+ 的通知权限弹窗

Android 13（API 33）及以上首次开启后台重连时，App 会主动弹出系统通知权限请求框。
Android 12 及以下没有这个权限模型，直接开启即可。

### 3.3 进程被杀后的自动恢复

部分国产 ROM 在用户划掉最近任务时会**直接杀掉应用进程，且不会按 `START_STICKY` 重启前台服务**。

App 已针对这一点做了处理：

- 服务存活状态用**进程内内存标记**记录，进程被杀即自动清空；
- 重新打开 App 时，若发现「开关是开的但服务其实没跑」，会**按你原来的设置自动重新拉起**服务，并把界面上的陈旧状态文字纠正掉；
- 「诊断」页会留下一条事件：`检测到后台服务已停止，已按原设置重新启动`。

所以：**被划掉后重新点开图标即可**，不需要重新开关一次。

### 3.4 VPN 场景

开启 VPN 时认证不会被路由表带偏：Android 端在探测与登录期间会用 `bindProcessToNetwork` 把进程绑定到底层物理 Wi-Fi，再发起认证请求。**不会关闭 VPN，也不改变其他应用的流量。**

## 4. 三个页面

| 页面 | 作用 |
|---|---|
| **连接** | 状态卡（在线/需认证/离线）、账号密码表单、登录与刷新 |
| **设置** | 网络恢复自动刷新、前台自动刷新、后台自动重连、账号管理、结束本地会话 |
| **诊断** | 当前状态、后台重连状态、最近 50 条脱敏诊断事件（界面展示最新 10 条） |

诊断事件只包含脱敏文本，不含明文密码、完整 cookie 或 URL。

## 5. 故障排查

| 现象 | 原因与处理 |
|---|---|
| 开关显示「开」但后台没动静 | 先看「诊断」页事件：若提示"检测到后台服务已停止"，说明刚恢复过；仍无反应则确认系统通知是否被禁用（见 3.1） |
| 后台重连开着却没有任何通知 | 厂商 ROM 禁用应用通知，见 3.1 |
| 一直提示「尚未确认」 | 应用内 Python 桥接未就绪，重新登录一次即可 |
| 登录提示需要人工验证 | 校园网侧要求验证码，应用不做绕过，交给人工 |
| 登录成功后账号没存上 | 只在登录确认成功且勾选「保存此账号」时才会保存 |
| 账号按 SSID 预选不生效 | 未授予 Wi-Fi 名称读取权限，见 2.1 |
| 结束会话后校园网仍在线 | 「结束本次会话」只关应用内与后台的 Python 会话，**不会**向校园网服务器发送退出请求 |

## 6. 从源码构建（开发者）

仓库自带 Gradle Wrapper（Gradle 8.9），**无需自备 Gradle**，只要 JDK 17 与 Android SDK（compileSdk 35）：

```bash
cd android
printf 'sdk.dir=%s\n' "$ANDROID_HOME" > local.properties
./gradlew :app:assembleDebug          # 产物：app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:testDebugUnitTest      # 单元测试
./gradlew :app:lintDebug              # 静态检查
```

Windows 用 `gradlew.bat`。

依赖已缓存且当前网络不可达时，加 `--offline` 避免直连 Maven 重试造成长时间等待：

```bash
./gradlew --offline :app:assembleDebug
```

构建需要 `compileSdk 35`、`minSdk 26`、`targetSdk 35`，JDK 17+。Python 侧依赖由 Chaquopy 安装进 APK，构建时会把仓库里的 `oit_portal/` 与 `pyproject.toml` 暂存到构建目录再安装。

## 7. 已知限制

- **协议 Capture 未接入移动端**：本校协议已实测确认，移动端首装可以在没有 `protocol.json` 的情况下 fail-closed 登录。换学校或协议变动后再接入。
- 应用不提供"注销校园网会话"功能。门户侧的接口层端点已确认为 `http://172.16.11.54/eportal/InterFace.do?method=logout`（**不需要 `userIndex`**，仅凭 IP+MAC 即可让该客户端的门户会话失效），但 App 侧未接入。
- 后台"自动重登"的触发条件是探测结果为 CAPTIVE。由于 App 的探测请求携带自己的 session cookie，**外部注销打不掉 App 的会话**（AC 认这个 cookie），该路径目前无法从 App 外部触发验证。

> **Android 13+ 通知权限弹窗路径已于 2026-11-01 在红米 K50 Ultra（HyperOS 2 / Android 15 / API 35）上完成真机验收**，
> 允许 / 拒绝两条分支均通过，验收记录见 `android/validation/2026-11-01-redmi-android15/report.md`。
