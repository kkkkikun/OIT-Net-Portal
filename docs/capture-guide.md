# 阶段 0：一键抓包（约 2 分钟）

> 不用再手动 F12 了。向导会自动完成跳转链分析、表单解析、密码加密检测、试登录，
> 成功后**自动写好协议配置并保存会话**，之后 `oit-portal daemon` 直接可用。

## 操作步骤

1. 电脑连上校园 WiFi，保持**未登录**状态
   （如果已登录：在认证成功页点「注销」，或断开重连 WiFi）
2. 确认已装好本工具（`pip install -e .` 或 `pip install .`）
3. 运行：

   ```bash
   oit-portal capture
   ```

4. 按提示输入账号和密码（密码输入不回显）
5. 看到 ✅ 就完成了——协议已自动配置、SSO 会话已保存，直接跑 `oit-portal daemon`

## 向导会自动处理的事

| 步骤 | 说明 |
|------|------|
| 触发跳转链 | 自动探测拿 302，跟随到登录表单页 |
| 表单解析 | 提交端点、字段名、隐藏字段全部自动识别 |
| 验证码检测 | 发现验证码会停下来并说明（据观察你们学校没有） |
| 密码加密检测 | 扫页面与外链 JS 找 RSA 公钥；有则先试 RSA、失败再试明文 |
| 登录与上线 | 自动 POST → 跟随 code 回跳 → ePortal 上线 → 复测确认 |
| 自配置 | 成功后写 `protocol.json`，无需手改任何代码 |
| 会话保存 | SSO cookie 落盘，daemon 之后免密复用（约 5 小时~当天有效） |

## 万一失败的兜底

- 运行后看报告：`~/.config/oit-portal/capture-report.txt`（Windows: `%APPDATA%\oit-portal\capture-report.txt`）
- **报告已脱敏**：不含密码；cookie 只保留前 4 位；隐藏字段只记名字和长度
- 把报告内容发给维护者（Claude）即可，等价于完成了全部手动抓包

## 手动抓包（存档备用，一般用不到）

只在向导完全无法工作（如页面纯 JS 动态渲染）时使用，只需抓三样：

1. **表单页源码**：登录页右键「查看网页源代码」，全选复制
2. **登录请求**：F12 → Network → 勾 Preserve log → 正常登录一次 → 找到 POST 请求 → Payload 面板截图（密码值可打码）
3. **成功页**：登录后最终页面的 URL 和「复制外层 HTML」

同样发给维护者即可。
